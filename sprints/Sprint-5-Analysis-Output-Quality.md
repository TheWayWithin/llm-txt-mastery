## Problem Statement

The llms.txt files our tool generates have several quality issues that undermine user trust:

1. Grammar error: "1 content clusters" (singular/plural mismatch)
2. Descriptions truncated mid-sentence with "..."
3. Only 5 of 11 discovered pages analyzed (aggressive filtering or low tier limit interaction)
4. AI produces vague filler descriptions when page content is thin (CSR shells)

These are all **program bugs** -- separate from how any particular site is set up.

### Evidence

**Generated file for llmtxtmastery.com (2026-02-22):**
```
Generated by LLM.txt Mastery on 2026-02-22. 11 pages found, 5 analyzed, 5 included.
Average quality: 9/10. 1 content clusters, ~2,000 words total.
```
- "1 content clusters" -- grammar error
- About page description: "...though the sample content does not provide detailed..." -- truncated AND filler
- Blog page description: "...although the specific content sample does not provide detailed information." -- filler admission

## Root Cause Analysis

### Issue 1: Grammar -- "1 content clusters"

**File**: `server/routes.ts`, line ~2768
**Code**:
```typescript
metadataBlock += `${siteStructure.clusterCount} content clusters, ~${estimatedWordCount.toLocaleString()} words total.`;
```

**Root cause**: No conditional pluralization. The line above it correctly pluralizes "pages" (`totalFound === 1 ? 'page' : 'pages'`) but "clusters" was missed.

### Issue 2: Description truncation at 300 characters

**File**: `server/services/openai.ts`

**Two locations with identical truncation logic:**

**HTML fallback path** (lines 237-244):
```typescript
let finalDescription = description.substring(0, 300) || 'No description available';
if (description.length > 300) {
  const lastSpace = finalDescription.lastIndexOf(' ');
  if (lastSpace > 250) {
    finalDescription = finalDescription.substring(0, lastSpace) + '...';
  }
}
```

**AI analysis path** (lines 322-328):
```typescript
let enhancedDescription = aiResult.description || htmlResult.description;
if (enhancedDescription.length > 300) {
  const lastSpace = enhancedDescription.lastIndexOf(' ', 300);
  if (lastSpace > 250) {
    enhancedDescription = enhancedDescription.substring(0, lastSpace) + '...';
  }
}
```

**Root cause**: Hard 300-char limit with word-boundary truncation. The `lastSpace > 250` guard means if there's no space between char 250-300, it hard-cuts at 300 without "..." -- leaving a mid-word break. When truncation happens, the "..." suffix is added but the sentence is already incomplete.

**Additional factor**: The AI prompt (line ~282-297) asks for "150-300 chars" but the AI sometimes produces slightly longer descriptions that then get truncated.

### Issue 3: Pages analyzed vs pages found mismatch

**Context**: 11 pages found, only 5 analyzed. This is NOT a tier limit issue (starter=20, coffee=200).

**Filtering pipeline** (in order):

1. **filterRelevantPages()** in `server/services/sitemap.ts` (lines 1296-1457):
   - Removes assets (.jpg, .css, .js, etc.)
   - Removes admin/login/dashboard paths
   - Removes navigation paths (/tag/, /category/, pagination)
   - For the site's 11 sitemap entries, this shouldn't remove many (sitemap only has clean page URLs)

2. **Tier page limit** in `server/services/sitemap-enhanced.ts` (lines 139-170):
   - Applied after filtering: `pagesToAnalyze = relevantPages.slice(0, maxPages)`
   - With 25% buffer: `Math.ceil(tierLimit * 1.25)`
   - Starter tier: 20 * 1.25 = 25 pages max -- not the bottleneck for 11 pages

3. **deduplicateAndFilterPages()** in `server/services/link-utils.ts` (lines 12-100):
   - Near-duplicate title detection (80% similarity threshold)
   - Low-value page filtering via `isValidPage()`
   - **This is likely where pages are dropped** -- if CSR renders the same generic title for all pages, they look like duplicates

4. **Final tier trim** in `server/services/sitemap-enhanced.ts` (line 331):
   - `finalPages = uniquePages.slice(0, tierLimits.maxPagesPerAnalysis)`

**Most likely cause**: On a CSR site, all pages return the same `<title>` ("LLM.txt Mastery - AI-Ready Website Content Generator") and same meta description. The deduplication logic sees them as 80%+ similar and collapses them into one representative page, keeping only 5 of 11.

**Key function -- isValidPage()** in `link-utils.ts` (lines 224-270):
- Rejects pages with quality score <= 1
- Rejects error page titles ("404", "not found")
- Rejects pages with very short titles (< 5 chars)

### Fix 2: Improve description truncation

**File**: `server/services/openai.ts` -- both truncation locations (lines ~237-244 and ~322-328)

**Goals**:
- Increase limit from 300 to 400 chars (descriptions in llms.txt aren't display-constrained)
- Always truncate at sentence boundary when possible (period, exclamation, question mark)
- Fall back to word boundary only if no sentence break exists
- Never end with "..." if the sentence is complete

**Before** (both locations):
```typescript
let finalDescription = description.substring(0, 300) || 'No description available';
if (description.length > 300) {
  const lastSpace = finalDescription.lastIndexOf(' ');
  if (lastSpace > 250) {
    finalDescription = finalDescription.substring(0, lastSpace) + '...';
  }
}
```

**After** (extract to a shared helper):
```typescript
function truncateDescription(text: string, maxLength: number = 400): string {
  if (!text) return 'No description available';
  if (text.length <= maxLength) return text;

  // Try to end at a sentence boundary first
  const truncated = text.substring(0, maxLength);
  const lastSentenceEnd = Math.max(
    truncated.lastIndexOf('. '),
    truncated.lastIndexOf('! '),
    truncated.lastIndexOf('? ')
  );

  // Use sentence boundary if it's not too short (at least 60% of max)
  if (lastSentenceEnd > maxLength * 0.6) {
    return truncated.substring(0, lastSentenceEnd + 1); // Include the period
  }

  // Fall back to word boundary
  const lastSpace = truncated.lastIndexOf(' ');
  if (lastSpace > maxLength * 0.6) {
    return truncated.substring(0, lastSpace) + '...';
  }

  // Last resort: hard cut
  return truncated + '...';
}
```

Then use `truncateDescription(description)` in both locations.

### Fix 3: Reduce false deduplication of CSR pages

**File**: `server/services/link-utils.ts`, near-duplicate detection (lines ~47-73)

**Problem**: When a CSR site returns the same title for every page (e.g., "LLM.txt Mastery - AI-Ready Website Content Generator"), the 80% title similarity threshold collapses all pages into one.

**Fix**: Before comparing titles for similarity, check if the URLs are meaningfully different. If two pages have different URL paths (not just query params), they should NOT be deduplicated purely on title similarity.

**Current logic** (simplified):
```typescript
// Stage 2: Near-duplicate detection by title similarity
for (const page of finalPages) {
  const isDuplicate = uniquePages.some(existing =>
    titleSimilarity(existing.title, page.title) > 0.8
  );
  if (!isDuplicate) uniquePages.push(page);
}
```

**Improved logic**:
```typescript
// Stage 2: Near-duplicate detection by title similarity
// Only deduplicate if BOTH title AND URL path are similar
for (const page of finalPages) {
  const isDuplicate = uniquePages.some(existing => {
    const titlesAreSimilar = titleSimilarity(existing.title, page.title) > 0.8;
    if (!titlesAreSimilar) return false;

    // If titles are similar but URLs have different paths, keep both
    // (CSR sites often return same title for all pages)
    try {
      const existingPath = new URL(existing.url).pathname;
      const pagePath = new URL(page.url).pathname;
      if (existingPath !== pagePath) return false;
    } catch { /* fall through to title-only check */ }

    return true;
  });
  if (!isDuplicate) uniquePages.push(page);
}
```

This preserves deduplication for true duplicates (same path, different query strings) while preventing CSR-induced false positives.

### Fix 4: Improve AI fallback for thin content

**File**: `server/services/openai.ts`

**Problem**: When the AI can't extract meaningful content, it admits this in the description ("does not provide detailed information"). This meta-commentary becomes the page description in the llms.txt output.

**Two-part fix**:

**4a. Increase content sample size** (line ~280):
```typescript
// BEFORE:
const contentSample = htmlResult.rawText?.substring(0, 2000) || '';

// AFTER:
const contentSample = htmlResult.rawText?.substring(0, 4000) || '';
```

**4b. Add prompt instruction to avoid meta-commentary** (line ~282-297):

Add to the AI prompt:
```
CRITICAL: Never describe what you cannot see or what the content lacks. If the page content is thin or unavailable, write a brief factual description based on the URL path, page title, and any available meta tags. Do NOT say things like "the content does not provide detailed information" or "although the specific content sample does not provide detailed."
```

**4c. Post-process to catch filler phrases** -- add a check after AI response:
```typescript
// Detect and clean filler phrases from AI descriptions
const fillerPhrases = [
  'does not provide detailed',
  'specific content sample',
  'content does not provide',
  'although the specific',
  'though the sample content',
  'no detailed information available',
];

let description = aiResult.description;
const hasFiller = fillerPhrases.some(phrase =>
  description.toLowerCase().includes(phrase)
);

if (hasFiller) {
  // Fall back to a clean description from title + URL
  description = generateFallbackDescription(url, htmlResult.title);
}
```

Where `generateFallbackDescription()` produces something like:
```typescript
function generateFallbackDescription(url: string, title: string): string {
  const path = new URL(url).pathname.replace(/\//g, ' ').trim();
  const cleanTitle = title.replace(/ - .*$/, '').trim(); // Remove site name suffix
  return `${cleanTitle} page on ${new URL(url).hostname}.`;
}
```

This is minimal but honest -- far better than filler text that undermines trust.

## Risk Assessment

| Change | Risk | Mitigation |
|--------|------|------------|
| Increased description length (300 -> 400) | Slightly longer llms.txt files | 400 chars is still reasonable; llms.txt has no size constraint |
| Deduplication path check | Could allow more near-duplicates through | Only affects pages with different URL paths -- genuine duplicates still caught |
| Filler phrase detection | Could false-positive on legitimate descriptions | Phrases are very specific; fallback is short but accurate |
| Larger content sample (2000 -> 4000) | Slightly more tokens per AI call | Marginal cost increase (~$0.001/page); significantly better descriptions |
